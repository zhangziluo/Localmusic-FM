# 极简FM

一个零依赖、纯前端的本地音乐电台 PWA：导入本地音乐文件夹，随机播放，配合 Web Audio 合成的收音机底噪，做成一台可以离线使用的「极简 FM」。除本地曲库外，还可以把网络直播流绑定到频道按键上收听。

界面走复古仪表风：LED 状态条、数据卡片（时钟 / 频道 / 累计收听时长）、实体感按键与九宫格频道键盘。

## 功能特性

- **本地曲库**：递归扫描音乐文件夹，支持 `mp3 / flac / wav / ogg / m4a / opus / aac`
- **覆盖 / 追加导入**：可一次性替换曲库，也可多次追加（按「文件名 + 相对路径」去重）
- **随机播放**：播放结束自动切下一首；上一首 / 下一首均为随机选曲
- **收藏**：红心标记，收藏列表持久化；频道 2 只播放收藏曲目
- **频道键盘**：CH1 随机、CH2 收藏；CH3–CH9 在曲库超过 15 首后解锁
- **按序号点歌**：先按 `#` 进入选号态，输入序号后按 `#` 确认，直接跳到第 N 首（序号按导入顺序 1 起算；`1` 随机 / `2` 红心不可选，有效范围 `3`–曲目总数）。若该编号已绑定网络串流，则优先播放串流
- **网络串流**：在设置里添加直播 / 点播流，可绑定到实体键 `3`–`9`、`0`，或编号 `10`–`9999`（最多保存 1000 条）；实体键直接点击收听，编号用 `#` 选号播放
- **网页跳转**：先按 `*` 进入跳转态，输入 `0`–`999999` 的编号，再按 `*` 在新窗口打开该编号绑定的网址；默认内置 `1` / `2` / `3` 三个常用电台网站，可在设置里增删改
- **播放记录导出**：自动记录每次本地曲目的播放时间，可按「今天 / 昨天 / 近 7 天」或自定义起止时间导出为 `.m3u` 播放列表
- **录制**：音乐推子下方的 ⏺️ 按钮可把当前本地曲目或网络串流录成音频文件；串流需同源或服务端允许 CORS，否则按钮置灰并提示
- **整点报时**：播放中每逢整点，先按 12 小时制响对应声数的「哔」，再用系统 TTS 播报「现在是北京时间下午一点整」；地点按设备时区推断（中国时区 → 北京，否则当地城市），报时期间暂停播放、结束自动继续
- **五套整页主题**：默认黑底橙字、LED 灰底黑字、冷光绿示波器、暖白奶油卡带机、暗红琥珀真空管，另有 8 种强调色
- **收音机底噪**：合成粉红噪声 + 海浪音频（`waves-Ds5uwdFe.mp3`）混合成一个底噪通道，经同一个增益节点统一控制
- **极简双推子**：界面直接调节「音乐音量」与「底噪音量」，0–100% 实时生效，播放中平滑过渡
- **复古数据卡片**：用 DSEG14 七段数码管字体显示实时时钟、频道（CH）和累计时长（TIME）；时长按 `0000:00:00` 显示，达到 `9999:59:59` 后再增加即归零；归零瞬间会触发 0.2 秒「重启」效果
- **PWA / 离线**：可安装到桌面或主屏幕，首次加载后离线可用
- **自动恢复曲库**：在支持 File System Access API 的浏览器中记住文件夹授权，下次打开自动恢复；授权失效时保留曲库索引，点击播放重新授权即可
- **键盘操作**：空格播放 / 暂停，左右方向键切歌，数字与 `*` / `#` 映射到屏幕按键（`#` 点歌、`*` 网页跳转）

## 快速开始
项目没有构建步骤、没有依赖，任何静态服务器都能直接跑：

```bash
cd fmradio
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000
```

也可以使用 Node 自带工具或任意静态服务器，例如：

```bash
npx serve .
```

> **不要直接双击 `index.html`（`file://`）使用。**
> Service Worker 只能在 `http(s)://` 或 `localhost` 下注册；文件夹句柄的持久化也依赖安全上下文。通过 `file://` 打开时仍能播放和导入，但没有离线能力，也无法自动恢复文件夹。

### 安装为 App

- **Chrome / Edge（桌面）**：地址栏右侧的「安装」图标，或菜单 → 投放、保存和共享 → 安装页面
- **Safari（macOS）**：文件 → 添加到程序坞
- **Android Chrome**：菜单 → 添加到主屏幕
- **iPhone / iPad**：Safari 分享按钮 → 添加到主屏幕

## 使用说明

### 导入音乐

1. 点击控制栏最左侧的 **导入文件夹**（文件夹 + 向上箭头）会**覆盖**当前曲库
2. 点击第二个 **追加文件夹**（文件夹 + 加号）会把新文件夹加入当前曲库，重复曲目自动跳过
3. 支持选择子文件夹，扫描是递归的
4. 浏览器不支持目录选择 API 时，会自动回退到 `<input webkitdirectory>` 文件选择；此模式下**总是替换**曲库，且不会记住文件夹

再次打开页面时，Chromium 系浏览器会读取上次的文件夹句柄。若读取权限仍然有效，会自动重新扫描并恢复曲库；若授权已失效，曲库索引仍会保留（曲目数量、CH3–CH9 解锁状态和累计时长不会丢），点击播放时会弹出一次读取权限请求，授权后立即恢复文件并开始播放。

### 频道

| 频道 | 行为 | 解锁条件 |
| --- | --- | --- |
| CH1 | 全库随机 | 无 |
| CH2 | 仅播放已收藏曲目（无收藏时回退全库随机） | 无 |
| CH3–CH9 | 当前与 CH1 一样为全库随机，保留为扩展位 | 曲库超过 15 首 |

切歌（上一首 / 下一首）始终随机抽取，不会回退到上一首；但每次开始播放本地曲目都会写入一条播放记录（含时间戳），用于「导出播放记录」。

未解锁时按键变灰并显示「待解锁」；曲库超过 15 首后按键点亮、小字全部消失。若之后替换为更少的曲目，CH3–CH9 会重新锁定，当前频道自动退回 CH1。

`3`–`9`、`0` 若在设置里绑定了网络串流，点击会直接播放该流，不再切换频道。`#` 不参与网络串流，专用于按序号点歌 / 选台；`*` 专用于网页跳转。

### 按序号点歌 / 选台

曲目信息下方会常驻显示「已导入 N 首 · 选号 3–N」，据此可以按序号直达某一首：

1. 短按 `#` 进入选号态：数码屏显示 `#`，`#` 键开始呼吸提示
2. 按数字键输入序号（可多位，例如 `1` `2` → `#12`；首位不能是 `0`）
3. 再按 `#` 确认：该编号绑定了网络串流则播放串流，否则跳到第 N 首并立即播放

序号口径：按导入顺序、从 1 起算（第 N 首 = `state.tracks[N-1]`）。`1`（随机）和 `2`（红心）保留给频道，因此点歌范围为 `3`–曲目总数；输入为空、编号未绑定串流且 `< 3` 或超出总数时，LED 会提示范围并清空输入，可重新输入。

串流编号范围为 `10`–`9999`，不受曲目总数限制；例如曲库只有 20 首，仍可用 `#99#` 播放绑定在 `99` 的串流。编号同时存在串流与曲目时串流优先。

退出选号态：再按 `#`、按 `*`、按播放 / 切歌键，或 5 秒无操作自动取消。选号态下 `1`–`9` 与 `0` 都作为数字位，不会切频道或触发网络串流。

### 网络串流

1. 设置 → **网络串流** → `＋ 添加`，填写名称与流地址（`http://` / `https://`），再填写按键 / 编号：`3`–`9`、`0`，或 `10`–`9999`（留空自动分配空闲键，实体键用完后从 `10` 起分配）
2. 点 **完成** 后实体键小字显示流名，直接点击该键即可播放；编号 > 9 没有实体键，用 `#` 输入编号后确认播放
3. 最多保存 **1000** 条串流地址，设置面板标题右侧显示当前用量（如 `12 / 1000`）
4. 直播流没有总时长，进度条固定满格；播放结束不会自动跳回本地曲库
5. 正在播放的流被删除后，播放停止并回到 CH1

### 网页跳转

把常用电台 / 工具网站绑定到编号，用键盘就能一键打开：

1. 短按 `*` 进入跳转态：数码屏显示 `↗`，`*` 键开始呼吸提示
2. 按数字键输入编号（`0`–`999999`，可多位，例如 `1` `0` → `↗10`；单独 `0` 也是合法编号）
3. 再按 `*` 确认：在新窗口 / 新标签页打开该编号绑定的网址，数码屏闪一下 `↗编号` 后恢复频道

首次使用内置三个默认地址：`1` → `streamurl.link`、`2` → `roamdial.com`、`3` → `globalradio.app`。在 设置 → **网页跳转** 里可增删改，最多保存 **1000** 条，网址需以 `http://` 或 `https://` 开头。

未绑定的编号会提示「编号 N 未绑定网页」，不打开窗口。退出跳转态：再按一次 `*` 输入为空时仅提示、按 `#` 转入点歌、按播放 / 切歌键，或 5 秒无操作自动取消。跳转态下 `1`–`9` 与 `0` 都作为编号位，不会切频道或触发网络串流。

### 导出播放记录

设置面板底部提供「导出播放记录」，把指定时间段内播放过的本地曲目导出为 `.m3u`：

1. 选择 **今天 / 昨天 / 近 7 天** 任一预设，起止时间会自动填入（以本地时间为界）
2. 也可以手动修改起止时间（精确到分钟；结束时间包含该分钟最后一秒）
3. 点 **导出 .m3u**，浏览器会下载 `fm-YYYYMMDD-HHMMSS.m3u`

说明：

- 记录只包含**本地曲目**，网络串流不写入记录
- 每次调用 `playTrack()` 都会追加一条 `{ 曲名, 文件名, 相对路径, 时间戳 }`，最多保留 2000 条（超出丢弃最旧的）
- `.m3u` 中每行优先写相对路径（文件夹导入时有值），其次写文件名；由于 File System Access 导入拿不到相对路径，此时只能写文件名，若文件不在同一目录，播放器可能找不到
- 该时段没有记录时不会下载文件，只在面板内提示「该时段无播放记录」

### 录制

音乐推子下方有一个红色圆点按钮（⏺️），用于录制当前正在播放的声音：

1. 播放本地曲目或网络串流后，按钮自动变为可用（不可录时置灰，鼠标悬停显示原因）
2. 点一下开始录制，按钮变为红色呼吸灯，LED 显示「正在录制…」
3. 再点一下停止，浏览器自动下载 `fm-rec-YYYYMMDD-HHMMSS.webm`（Safari 可能为 `.mp4`）
4. 切歌 / 切换串流时若仍在录制，会先结束并保存当前录音

限制：

- **网络串流需要 CORS**：浏览器要求跨域媒体在 `crossorigin="anonymous"` 下可读，否则录音会是静音。页面会先用 `fetch(..., { mode: 'cors' })` 探测，只有同源或服务端返回允许跨域的响应头时才启用按钮
- 录音通过一个**独立的音频元素**接入 Web Audio，再送入 `MediaRecorder`，不会改变主播放器的音频路由
- 输出格式由浏览器决定：Chromium 通常为 `webm/opus`，Safari 为 `mp4/aac`，不会生成 mp3
- iOS Safari 对 `MediaRecorder` 支持有限，可能无法录制或只能录制部分格式
- 录制的是「从现在开始」的实时音频；本地曲目会从当前播放进度开始录，直播流则从建立录制连接的时刻开始

### 整点报时

播放本地曲目或网络串流时，每逢整点会自动报时：

- 先按 **12 小时制**响对应声数的「哔」：1 点 1 声、12 点 12 声、13 点 1 声
- 随后用系统 TTS 播报：`现在是北京时间下午一点整`
- 地点按设备时区推断（离线、不请求 IP）：中国时区（`Asia/Shanghai` 等）报「北京」，其余报当地城市（如 `Asia/Tokyo` → 东京；未内置的城市显示时区中的城市名）
- 报时期间暂停音乐 / 串流，哔声与播报结束后自动继续；若中途手动暂停则不再自动恢复
- 仅在播放中触发，暂停时不报；同一整点只报一次

### 设置面板

点击控制栏最右侧的齿轮打开设置：

| 设置项 | 说明 | 默认值 |
| --- | --- | --- |
| 主题色 | 8 种强调色，影响按钮、卡片数字、推子等 | `#ff8c42` 橙 |
| 界面主题 | 五套整页主题：默认 · 黑底橙字 / LED · 灰底黑字 / 冷光绿 · 示波器 / 暖白奶油 · 卡带机 / 暗红琥珀 · 真空管 | 默认 · 黑底橙字 |
| 底噪 | 播放时是否叠加收音机底噪（粉红噪声 + 海浪） | 关闭 |
| 口播间隔（首） | 预留给「每 N 首插入口播」功能，当前仅保存数值 | 0 |
| 网络串流 | 添加 / 删除流，绑定到 `3`–`9`、`0` 或编号 `10`–`9999`，最多 1000 条 | 无 |
| 网页跳转 | 添加 / 删除网址，绑定编号 `0`–`999999`，最多 1000 条 | `1`→streamurl.link、`2`→roamdial.com、`3`→globalradio.app |
| 导出播放记录 | 选择「今天 / 昨天 / 近 7 天」或自定义起止时间，导出该时段的本地曲目为 `.m3u` | 今天 |

「音乐音量」和「底噪音量」两个推子直接放在主界面，不在设置面板内。

保存规则：

- 其他设置项在点 **完成** 时统一保存
- 两个音量推子在**松开滑杆时立即保存**，点遮罩关闭也不会丢失
- 点面板外的遮罩只会关闭面板，不会保存未点「完成」的改动
- 网络串流的增删同样只在点 **完成** 时提交；点遮罩取消会丢弃这些改动（主题与强调色也会回滚）

## 实现说明

### 播放与曲库

- 使用 `Audio` 对象播放 `Blob URL`，`timeupdate` 驱动进度条
- 目录扫描通过 `FileSystemDirectoryHandle.entries()` 递归进行，按扩展名过滤
- 文件夹句柄存入 IndexedDB；刷新时读取句柄并检查 `queryPermission`，授权仍有效则自动重新扫描并生成可播放的 `File` 列表
- 授权失效时从 `localStorage` 的 `fm_library` 立即恢复曲库索引；首次播放操作会调用 `requestPermission`，授权后重新扫描文件
- 不支持 `showDirectoryPicker` 时回退到 `<input type="file" webkitdirectory multiple>`
- 曲名自动去掉扩展名；收藏以「去扩展名的文件名」为键

### 网络串流

- 串流地址直接赋给 `audio.src`，不经代理，也不占用 Blob URL
- `state.mode === 'stream'` 时 `ended` 不会自动切回本地曲库，进度条固定 100%
- 绑定保存在 `fm_streams`；`loadStreams()` 会过滤非 `http(s)` 地址与结构非法的条目，并限制最多 `MAX_STREAMS = 1000` 条
- 键位由 `parseStreamKey()` 校验：实体键 `3`–`9`、`0`，或编号 `3`–`9999`（前导 0 归一化；`1` / `2` 保留）；`#` 与 `*` 均不参与串流绑定
- 编号 > 9 没有实体键，通过 `#` 选号触发：确认时先查 `state.streams[String(N)]`，命中即 `playStream()`，未命中再按点歌范围处理

### 网页跳转

- 状态机 `web = { active, buf, timer }`：`startWebJump()` 进入并把 `#dash-ch` 显示为 `↗`，`webDigit(d)` 追加编号（最多 `MAX_WEB_DIGITS = 6` 位），`confirmWebJump()` 查表后用 `window.open(url, '_blank', 'noopener,noreferrer')` 打开
- 绑定保存在 `fm_webjumps`：编号 → URL 字符串；`loadWebLinks()` 首次使用写入内置默认 `{1,2,3}`，之后逐条过滤非 `http(s)` 地址 / 非字符串 / 超范围编号，并限制 `MAX_WEB_LINKS = 1000` 条
- 编号由 `parseWebKey()` 校验：`0`–`999999`（前导 0 归一化）
- 数码屏闪动：跳转态给 `#dashboard` 加 `.dash-link`（`↗` 脉冲）；确认后 `.dash-link-flash` 闪一下就 `renderDash()` 恢复频道
- 与选号态互斥：`startWebJump()` 会 `cancelDial(true)`，`startDial()` 会 `cancelWebJump(true)`；`*` 在选号态下仍优先取消选号

### 按序号点歌 / 选台

- 选号态由 `dial = { active, buf, timer }` 维护；`#` 进入 / 确认，数字键累加到 `buf`，`*`、播放 / 切歌键或 5 秒超时退出
- 确认时解析 `buf` 为整数 `N`，优先匹配 `state.streams[String(N)]`；未绑定串流时校验 `3 ≤ N ≤ state.tracks.length`，通过后调用 `playTrack(state.tracks[N-1])`
- 只有串流编号、曲目不足 3 首时仍可进入选号态（`hasNumericStreams()`），避免纯串流用户被挡
- 文件夹授权失效时先 `ensurePlayable()` 重新扫描，再按文件名找回目标曲目
- 选号期间数码屏复用 `#dash-ch` 显示 `#` + 输入，退出时恢复频道 / 串流键位显示

### 整点报时

- `updateClock()` 每秒调用 `maybeChime(now)`：`分 === 0` 且 `秒 ≤ 2` 才触发，容忍定时器漂移
- 去重键 `lastChimedKey` = `年-月-日-时`，同一小时只报一次；`chiming` 标志防重入
- 哔声由 `playChimeBeeps(count, done)` 用 Web Audio `OscillatorNode`（880Hz，140ms 响 + 260ms 间隔）合成，不依赖音频文件
- 文案 `buildChimeText()`：12 小时制 + 时段（凌晨 / 上午 / 中午 / 下午 / 晚上），中文数字（一点、两点、十二点）
- 地点 `resolveLocation(tz)`：中国时区 → 北京；内置常见城市中译（东京 / 纽约…）；其余取时区最后一段并把 `_` 换成空格
- TTS `speakChime()`：`speechSynthesis.speak()`，由 `onend` / `onerror` / 超时兜底进入 `finishChime()`
- 报时前 `audio.pause()` 并记录 `chimeResume`；结束后仅当 `state.playing` 仍为真才 `audio.play()` 恢复
- 后台标签页的定时器可能被浏览器节流，整点可能延迟甚至跳过；自动恢复也受浏览器自动播放策略影响

### 播放记录与导出

- `recordPlay(t)` 在每次 `playTrack()` 时追加 `{ name, fileName, path, ts }`，同步写入 `localStorage` 的 `fm_history`；超过 `MAX_HISTORY = 2000` 条时丢弃最旧的
- `presetRange(preset, now?)` 返回 `[start, end]`：今天 = 本地零点至当前，昨天 = 前一天零点至今天零点，近 7 天 = 当前时间往前 7×24 小时
- `buildM3u(list)` 生成带 `#EXTM3U` 头的纯路径列表，每行优先 `path`，其次 `fileName`，再次 `name`；空条目跳过
- 导出时按 `ts ∈ [start, end]` 过滤并按时间升序排列；`end` 取所选分钟的最后一毫秒（`+59999ms`），避免同分钟记录被截断
- 下载通过 `Blob` + 临时 `<a download>` 完成，文件名为 `fm-YYYYMMDD-HHMMSS.m3u`；空结果不下载
- 限制：File System Access API 不提供相对路径，`path` 为空时只能导出文件名

### 录制

- `canRecordUrl(url)`：同源直接通过；跨域用 `fetch(url, { mode: 'cors' })` 探测，成功缓存为可录、失败缓存为不可录（缓存键为 URL）
- `refreshRecordButton()` 根据播放状态、来源类型与 CORS 结果设置 `#btn-record` 的 `disabled` / `title`；异步检测带 token 校验，防止流已切换时写入过期结果
- `startRecording()` 创建**独立**的 `Audio` 元素（跨域串流设 `crossOrigin = 'anonymous'`），经 `createMediaElementSource` 接入已有的 `AudioContext`，只连到 `createMediaStreamDestination()`，因此不会改变主播放器的出声路由，也不会让主播放器永久受 CORS 污染
- `MediaRecorder` 每 1 秒收集一次数据；停止后合并为 `Blob` 并下载。MIME 优先级：`audio/webm;codecs=opus` → `audio/webm` → `audio/ogg;codecs=opus` → `audio/mp4`
- 本地曲目会等 `loadedmetadata` 后把录音元素 `currentTime` 对齐主播放器；录音元素 `ended` / `error` 时自动收尾
- 切歌、切换串流时若正在录制，会先结束并保存当前录音

### 数码管字体

数据卡片使用开源的 **DSEG14 Classic**（SIL OFL 1.1）：

- 时钟、频道数字、时长数字使用 Bold 字重
- `CH` / `TIME` 标签使用 Regular 字重
- 字体以 woff2 本地嵌入 `fonts/`，随 Service Worker 预缓存，离线可用，不依赖外部 CDN
- `@font-face` 只声明 400 / 700 两个字重，使用 `font-display: swap`

### 底噪（粉红噪声 + 海浪）

底噪通道由两层叠加而成，经同一个 `GainNode`（`noiseGain`）输出，因此「底噪」推子同时控制两层的混合音量：

| 层 | 来源 | 说明 |
| --- | --- | --- |
| 粉红噪声 | Web Audio 实时合成 | Paul Kellet 多级一阶滤波器，26 万级 Float32 采样生成 4 秒单声道 `AudioBuffer` 循环播放 |
| 海浪 | `waves-Ds5uwdFe.mp3` | 通过 `<audio loop>` + `createMediaElementSource` 流式接入 Web Audio，与粉红层共同进入 `noiseGain` |

细节：

- 粉红噪声按 RMS 归一化到 `0.08`；海浪元素自身音量固定 `0.8`，两层响度接近
- 粉红噪声循环接缝：额外生成 150 ms 尾部并与头部交叉淡化，避免循环点「啪」声
- 缓冲按采样率缓存（只有一种类型，键为 `采样率:pink`）
- 淡入 300 ms、停止淡出 250 ms；海浪元素在淡出结束后才 `pause()`，避免突然截断
- 音量变化用 120 ms 线性斜坡，拖动推子不会产生爆音
- 底噪只在音乐播放时出现：`play` 启动、`pause` 停止；第一次点击 / 按键会解锁 `AudioContext`（iOS / Safari 必需）
- 若 `createMediaElementSource` 失败（如 `file://` 打开），会跳过海浪层并保留粉红噪声

### Service Worker 缓存策略（`fm-pwa-v20`）

| 请求类型 | 策略 |
| --- | --- |
| 页面导航（`mode === 'navigate'`） | 网络优先，成功则写入缓存；离线回退缓存 / `index.html` |
| 同源静态资源（GET） | 缓存优先，同时后台请求并更新缓存（stale-while-revalidate） |
| 跨域请求、非 GET 请求 | 直接放行，不拦截 |

- `install` 预缓存 `./`、`index.html`、`style.css?v=11`、`app.js?v=12`、`manifest.json`、两个图标与两个字体文件，并 `skipWaiting()`
- `activate` 删除旧版本缓存并 `clients.claim()`
- 页面检测到新版本安装完成时，LED 状态条会提示「新版本已就绪 · 刷新后生效」

## 已知限制

- **上一首不是历史回退**：上一首 / 下一首都从曲库随机抽取
- **CH3–CH9 暂为占位**：解锁条件已生效，但播放逻辑目前与 CH1 相同
- **口播间隔尚未实现**：设置值会保存，但不会真的插入口播
- **收藏按文件名去重**：不同文件夹中的同名歌曲会互相覆盖收藏状态
- **点歌序号依赖导入顺序**：序号按当前 `state.tracks` 顺序计算，重新导入 / 恢复后顺序可能变化；`1`（随机）与 `2`（红心）恒不可选
- **网络串流受浏览器限制**：`https` 页面无法播放 `http` 流（mixed content）；HLS（`.m3u8`）在 Chrome / Firefox 上通常无法直接播放，需 Safari 或额外解析库
- **自动恢复仅 Chromium 系**：Safari / Firefox 回退模式下每次打开都需要重新选择文件，且追加按钮等同于覆盖；回退模式仍会保留曲库索引，但无法在重新选择前播放
- **收听时长的落盘时机**：播放中每 15 秒、暂停 / 播放结束、页面隐藏或关闭时写入；正常刷新 / 关闭不会丢失，浏览器被强制终止时最多丢失最近 15 秒
- **收听时长上限**：显示上限为 `9999:59:59`，继续累计会归零重新计时；归零时若正在播放，会触发 0.2 秒的屏幕熄灭与底噪中断效果
- **Blob URL 只保留当前一首**：切歌时会回收上一个 `URL.createObjectURL`；网络串流直接使用远程地址，不创建 Blob URL
- **无锁屏 / 媒体键控制**：未接入 Media Session API，锁屏信息与耳机按键依浏览器默认行为而定
- **iOS 后台限制**：切到后台或锁屏后播放可能被系统暂停；底噪需要用户手势后才能启动
- **整点报时依赖系统语音**：TTS 声音由操作系统提供，缺少中文语音时可能读英文或不出声；后台标签页的定时器被节流时，整点报时可能延迟或跳过
- **报时后的自动恢复**：结束报时若 `audio.play()` 被浏览器自动播放策略拒绝，会停在暂停状态，需要手动点播放
- **导出的 .m3u 只有文件名时可能找不到曲目**：File System Access 导入不暴露相对路径，若曲目分散在多个子目录，播放器无法仅凭文件名定位；文件夹整体移动到播放器可访问的位置后可正常使用
- **跨域串流不能录制**：若流服务器未返回 `Access-Control-Allow-Origin`，`MediaRecorder` 只能录到静音，因此按钮会置灰；这是浏览器安全限制，无法在前端绕过
- **录制格式不是 mp3**：浏览器只提供 `webm` / `ogg` / `mp4` 容器，需要 mp3 时得自行转码
- **录音在页面关闭时可能丢失**：`MediaRecorder` 数据每秒落一次内存，页面被强制关闭时最后一段不会保存；停止录制后才会生成并下载文件
- **更新缓存需改版本号**：修改静态文件后若不修改 `sw.js` 的 `CACHE`，已安装的旧客户端可能首次仍使用旧缓存，刷新后才更新

## 开发与调试

```bash
# 语法检查（无构建、无测试框架）
node --check app.js
node --check sw.js
```

发布更新时：

1. 修改 `app.js` / `style.css` / `index.html` 等静态资源
2. 把 `sw.js` 第一行的 `CACHE` 改成新版本号（例如 `fm-pwa-v20`），确保旧缓存被清理；同时更新 `index.html` 中的 `style.css?v=`、`app.js?v=` 与 `sw.js` 的 `ASSETS`
3. 本地起 HTTP 服务验证；若浏览器仍显示旧版，可在 DevTools → Application → Service Workers 中 Unregister，或执行「清空缓存并硬性重新加载」

调试常用入口：

```js
localStorage.getItem('fm_config')   // 查看设置
localStorage.getItem('fm_favs')     // 查看收藏
localStorage.getItem('fm_streams')  // 查看网络串流绑定
localStorage.getItem('fm_history')  // 查看播放记录（导出 .m3u 的数据源）
localStorage.clear()                // 重置设置与收藏（需刷新）
```
