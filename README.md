# 极简FM

一个零依赖、纯前端的本地音乐电台 PWA：导入本地音乐文件夹，随机播放，配合 Web Audio 合成的收音机底噪，做成一台可以离线使用的「极简 FM」。

界面走复古仪表风：LED 状态条、数据卡片（时钟 / 频道 / 累计收听时长）、实体感按键与九宫格频道键盘。

## 功能特性

- **本地曲库**：递归扫描音乐文件夹，支持 `mp3 / flac / wav / ogg / m4a / opus / aac`
- **覆盖 / 追加导入**：可一次性替换曲库，也可多次追加（按「文件名 + 相对路径」去重）
- **随机播放**：播放结束自动切下一首；上一首 / 下一首均为随机选曲
- **收藏**：红心标记，收藏列表持久化；频道 2 只播放收藏曲目
- **九宫格频道**：CH1 随机、CH2 收藏；CH3–CH9 需曲库 ≥ 100 首解锁
- **收音机底噪**：粉红噪声 / 棕色噪声 / 电台沙沙声三种，全部由 Web Audio 实时合成，不依赖任何外部音频文件
- **底噪音量滑杆**：0–100% 实时调节，播放中平滑过渡，默认 85%
- **复古数据卡片**：实时时钟 + 当前频道 + 累计收听时长；支持「黑底橙字」和「LED 灰底黑字」两种风格
- **主题色**：8 种强调色即时切换
- **PWA / 离线**：可安装到桌面或主屏幕，首次加载后离线可用
- **自动恢复曲库**：在支持 File System Access API 的浏览器中记住文件夹授权，下次打开自动恢复
- **键盘操作**：空格播放 / 暂停，左右方向键切歌

## 快速开始

项目没有构建步骤、没有依赖，任何静态服务器都能直接跑：

```bash
cd fmradio
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000
```

也可以使用 Node 自带工具或任意静态服务器，例如：

```bash
npx serve .
```

> **不要直接双击 `index.html`（`file://`）使用。**
> Service Worker 只能在 `http(s)://` 或 `localhost` 下注册；文件夹句柄的持久化也依赖安全上下文。通过 `file://` 打开时仍能播放和导入，但没有离线能力，也无法自动恢复文件夹。

### 安装为 App

- **Chrome / Edge（桌面）**：地址栏右侧的「安装」图标，或菜单 → 投放、保存和共享 → 安装页面
- **Safari（macOS）**：文件 → 添加到程序坞
- **Android Chrome**：菜单 → 添加到主屏幕
- **iPhone / iPad**：Safari 分享按钮 → 添加到主屏幕

## 使用说明

### 导入音乐

1. 点击控制栏最左侧的 **导入文件夹**（文件夹 + 向上箭头）会**覆盖**当前曲库
2. 点击第二个 **追加文件夹**（文件夹 + 加号）会把新文件夹加入当前曲库，重复曲目自动跳过
3. 支持选择子文件夹，扫描是递归的
4. 浏览器不支持目录选择 API 时，会自动回退到 `<input webkitdirectory>` 文件选择；此模式下**总是替换**曲库，且不会记住文件夹

再次打开页面时，Chromium 系浏览器会尝试恢复上次的文件夹；若授权已失效，会弹出一次读取权限请求。

### 频道

| 频道 | 行为 | 解锁条件 |
| --- | --- | --- |
| CH1 | 全库随机 | 无 |
| CH2 | 仅播放已收藏曲目（无收藏时回退全库随机） | 无 |
| CH3–CH9 | 当前与 CH1 一样为全库随机，保留为扩展位 | 曲库 ≥ 100 首 |

切歌（上一首 / 下一首）不会记录播放历史，始终随机抽取；切换频道会重置播放队列状态并立即开始播放一首。

### 设置面板

点击控制栏最右侧的齿轮打开设置：

| 设置项 | 说明 | 默认值 |
| --- | --- | --- |
| 主题色 | 8 种强调色，影响按钮、卡片数字、滑杆等 | `#ff8c42` 橙 |
| 数据卡片 | 「黑底橙字」或「LED 灰底黑字」 | 黑底橙字 |
| 底噪 | 播放时是否叠加收音机底噪 | 关闭 |
| 底噪类型 | 粉红噪声 / 棕色噪声 / 电台沙沙声 | 粉红噪声 |
| 底噪音量 | 0–100%，拖动时实时生效 | 85% |
| 口播间隔（首） | 预留给「每 N 首插入口播」功能，当前仅保存数值 | 0 |

保存规则：

- 其他设置项在点 **完成** 时统一保存
- 底噪音量在**松开滑杆时立即保存**，点遮罩关闭也不会丢失
- 点面板外的遮罩只会关闭面板，不会保存未点「完成」的改动

### 快捷键

| 按键 | 功能 |
| --- | --- |
| `Space` | 播放 / 暂停 |
| `←` | 上一首（随机） |
| `→` | 下一首（随机） |

## 实现说明

### 播放与曲库

- 使用 `Audio` 对象播放 `Blob URL`，`timeupdate` 驱动进度条
- 目录扫描通过 `FileSystemDirectoryHandle.entries()` 递归进行，按扩展名过滤
- 文件夹句柄存入 IndexedDB；刷新时读取句柄并检查 `queryPermission / requestPermission`
- 不支持 `showDirectoryPicker` 时回退到 `<input type="file" webkitdirectory multiple>`
- 曲名自动去掉扩展名；收藏以「去扩展名的文件名」为键

### 底噪合成

所有底噪都在首次需要时用 Web Audio 生成 4 秒单声道 `AudioBuffer`，循环播放，无网络请求：

| 类型 | 合成方式 | 听感 |
| --- | --- | --- |
| `pink` 粉红噪声 | Paul Kellet 多级一阶滤波器 | 均衡、柔和，类似调频空闲频段 |
| `brown` 棕色噪声 | 白噪声泄漏积分（约 -6 dB/oct） | 更低、更厚重，类似低频轰鸣 |
| `static` 电台沙沙声 | 350 Hz 高通 + 7 kHz 低通，叠加随机爆音与缓慢信号漂移 | 老式收音机无台时的沙沙声 |

细节：

- 统一响度：按 RMS 归一化到 `0.08`，其中沙沙声再乘 `0.85`，三种底噪切换时音量接近
- 循环接缝：额外生成 150 ms 尾部并与头部交叉淡化，避免循环点「啪」声
- 缓冲按 `采样率:类型` 缓存，切换回已用过的类型无需重新生成
- 淡入 300 ms、停止淡出 250 ms；切换类型先淡出 180 ms，220 ms 后淡入新类型
- 音量变化用 120 ms 线性斜坡，拖动滑杆不会产生爆音
- 底噪只在音乐播放时出现：`play` 启动、`pause` 停止；第一次点击 / 按键会解锁 `AudioContext`（iOS / Safari 必需）

### Service Worker 缓存策略（`fm-pwa-v3`）

| 请求类型 | 策略 |
| --- | --- |
| 页面导航（`mode === 'navigate'`） | 网络优先，成功则写入缓存；离线回退缓存 / `index.html` |
| 同源静态资源（GET） | 缓存优先，同时后台请求并更新缓存（stale-while-revalidate） |
| 跨域请求、非 GET 请求 | 直接放行，不拦截 |

- `install` 预缓存 `./`、`index.html`、`style.css`、`app.js`、`manifest.json` 和两个图标，并 `skipWaiting()`
- `activate` 删除旧版本缓存并 `clients.claim()`
- 页面检测到新版本安装完成时，LED 状态条会提示「新版本已就绪 · 刷新后生效」

### 本地数据

| 存储位置 | 键 / 库 | 内容 |
| --- | --- | --- |
| `localStorage` | `fm_config` | `totalPlayTime`、`noiseOn`、`noiseType`、`noiseVolume`、`voiceInterval`、`accent`、`cardStyle` |
| `localStorage` | `fm_favs` | 收藏曲名数组（不含扩展名） |
| IndexedDB | `fm-pwa-db` / `handles` / `music-dir` | 上次选择的音乐文件夹句柄 |

清空站点数据会同时丢失设置、收藏和文件夹授权（不会删除本地音乐文件）。

## 已知限制

- **上一首不是历史回退**：上一首 / 下一首都从曲库随机抽取
- **CH3–CH9 暂为占位**：解锁条件已生效，但播放逻辑目前与 CH1 相同
- **口播间隔尚未实现**：设置值会保存，但不会真的插入口播
- **收藏按文件名去重**：不同文件夹中的同名歌曲会互相覆盖收藏状态
- **自动恢复仅 Chromium 系**：Safari / Firefox 回退模式下每次打开都需要重新选择文件，且追加按钮等同于覆盖
- **收听时长非实时落盘**：在暂停、播放结束或保存设置时写入；播放中直接关闭标签页会丢失当前这一段时长
- **Blob URL 未回收**：每次播放都会创建新的 `URL.createObjectURL` 且未 `revokeObjectURL`，大量切歌后内存会逐渐累积
- **无锁屏 / 媒体键控制**：未接入 Media Session API，锁屏信息与耳机按键依浏览器默认行为而定
- **iOS 后台限制**：切到后台或锁屏后播放可能被系统暂停；底噪需要用户手势后才能启动
- **更新缓存需改版本号**：修改静态文件后若不修改 `sw.js` 的 `CACHE`，已安装的旧客户端可能首次仍使用旧缓存，刷新后才更新

## 开发与调试

```bash
# 语法检查（无构建、无测试框架）
node --check app.js
node --check sw.js
```

发布更新时：

1. 修改 `app.js` / `style.css` / `index.html` 等静态资源
2. 把 `sw.js` 第一行的 `CACHE` 改成新版本号（例如 `fm-pwa-v4`），确保旧缓存被清理
3. 本地起 HTTP 服务验证；若浏览器仍显示旧版，可在 DevTools → Application → Service Workers 中 Unregister，或执行「清空缓存并硬性重新加载」

调试常用入口：

```js
localStorage.getItem('fm_config')   // 查看设置
localStorage.getItem('fm_favs')     // 查看收藏
localStorage.clear()                // 重置设置与收藏（需刷新）
```
